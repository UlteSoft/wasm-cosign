# WSEA Studio — 中文使用说明

[English](README.en_US.md) · [文档索引](README.md)

WSEA Studio 是调用现有 wasm-cosign 本机程序的 Python 图形界面。主导航只提供 **签名、校验、更多工具**。策略创建、策略更新和 HTTPS 获取统一归入“更多工具”。切换中英文会保留表单内容。

## 启动

需要准备：

- Python 3.10 或更新版本，以及已有的 wasm-cosign WSEA v2 本机可执行文件。
- 本机图形桌面。Linux 优先使用已安装的 `zenity`；未安装时使用 Python `tkinter`。Windows 和 macOS 使用 `tkinter` 文件对话框。如缺少相应桌面组件，请自行安装；Web GUI 不会安装依赖。
- 启用 JavaScript 的浏览器。无需前端构建、包管理器、CDN 或第三方网站服务。

```sh
python3 webgui/server.py --binary /absolute/path/to/cosign
```

打开终端显示的私密会话链接。服务只监听 `127.0.0.1`，默认端口为 `8765`。`--port 0` 自动选择空闲端口；`--timeout 120` 设置主程序运行时限，范围为 1–3600 秒。按 Ctrl+C 停止服务。

Web GUI 不会编译、下载或替换主程序。文件对话框在 Python 所在的计算机上打开，因此应在本机桌面会话启动，而不是无桌面的远程终端。请使用可信的可执行文件；启动时的版本检查用于判断兼容性，不用于证明可执行文件的来源。

网页读取会话令牌后会从地址栏移除，只在内存中保存。刷新页面需重新使用会话链接。表单和所选文件名不会写入浏览器持久存储。请保管好会话链接，不要通过代理或端口转发对外开放此本地服务。

## 选择本地文件

点击 **选择文件**，使用系统文件对话框完成选择。浏览器只接收你主动选中的文件名，以及本次会话内随机生成的标识。绝对路径、目录列表和私钥内容不会通过 HTTP 接口返回。点击文件旁的 × 可以移除选择，也可以重新选择。

**选择保存位置** 打开系统保存对话框。请指定新的输出文件名。创建状态目录时，在对话框中指定新目录的名称及父目录位置，由主程序创建。文件所有者、权限、符号链接、独占创建和已有状态检查仍由主程序执行。

旧的网页目录浏览器、路径输入框、命令预览、原始控制台输出和环境页面已经移除，`--browse-root` 参数不再适用。不同用途的文件标识不能互换，例如不能把私钥选择当成输出文件或策略。只有成功操作后主动进入后续操作，输出标识才会转换成可读取的模块或策略标识。

## 签名

1. 选择 WASM 模块、信任策略、私钥、签名证书链和 CRL，并选择新输出位置。确需写回原文件时，在第一步的 **高级选项** 中启用 **原地签名**。
2. 点击 **下一步**，填写模块标识和版本，选择算法及有效期。日期控件明确使用 UTC，服务器接收 RFC3339 时间。1、7、30 天快捷按钮会根据当前时间重新设置有效期起止时间。
3. 按需打开第二步的 **高级选项**，设置追加或替换模式、安全纪元、能力位掩码及多签中间文件选项。
4. 点击 **开始签名**。结果明确区分已完成完整校验的签名和仍需更多签名者的中间文件。

默认创建签名。**替换全部签名** 会替换模块已有的全部签名贡献；**追加签名** 会校验已有贡献，并要求清单保持一致。选择新输出不允许覆盖已存在文件；原地模式则以原子方式写回所选输入文件。

| 字段 | CLI 参数 | 要求 |
| --- | --- | --- |
| WASM 模块 | `<module>` | 必填，现有模块 |
| 信任策略 | `--policy` | 必填，现有受保护策略 |
| 输出文件 | `--output` | 新文件；原地替换模式不填写 |
| 私钥文件 | `--key` | 必填，PEM，密钥类型与算法匹配 |
| 签名证书链 | `--certificate` | 必填，PEM 叶证书在前，中间证书随后 |
| CRL 证据包 | `--crl` | 必填，完整且有效的 CRL 包 |
| 签名算法 | `--algorithm` | 默认 `ES256`，须在策略允许集合中 |

| 字段 | CLI 参数 | 格式 / 初值 |
| --- | --- | --- |
| 模块标识 | `--module-id` | 策略中已授权的标识 |
| 模块版本 | `--module-version` | 无符号 64 位整数，初值 `1` |
| 安全纪元 | `--security-epoch` | 无符号 64 位整数，初值 `0` |
| 能力位掩码 | `--capabilities` | `0`–`63`，初值 `0` |
| 生效时间 | `--not-before` | RFC3339 时间，初值为打开页面前 1 分钟 |
| 截止时间 | `--not-after` | RFC3339 时间，初值为打开页面后 24 小时 |

无符号整数通过 JavaScript 和 JSON 时始终保留十进制字符串形式，避免 uint64 精度损失。支持的算法为 `ES256`、`ESP256`、`ES384`、`ESP384`、`ES512`、`ESP512`、`Ed25519`、`PS256`、`PS384`、`PS512`、`RS256`、`RS384`、`RS512`。所选算法和签名者必须获得受保护策略的授权。

## 多签流程

以 ECDSA、RSA、Ed25519 的 3/3 策略为例：

1. 在“更多工具”中创建策略，选择三个授权证书，允许 `ES256`、`RS256`、`Ed25519`，并把门槛设为 `3`。
2. 使用第一把密钥签名，启用 **允许多签中间文件**。中间签名不代表完整校验成功。
3. 点击结果中的 **追加签名**。模块、策略和清单自动沿用；私钥、证书、CRL 和输出选择自动清空。
4. 选择下一签名者的文件及新输出，进入签名设置并选择对应算法。收集完最后一个签名之前保留中间文件选项。
5. 最后一个签名关闭中间文件选项，以要求达到完整门槛。完成后点击 **校验此文件**，执行独立的完整校验。

最多支持八个签名贡献。门槛统计的是不同的授权公钥，而不是签名次数；相同密钥重复签名不会增加独立签名者数。结果分别显示该数量和各贡献的算法。中间文件不能通过完整校验或 HTTPS 获取。已有签名和共享清单仍由主程序校验。

## 校验与获取

**校验** 只需选择模块和信任策略。成功表示主程序的签名校验、门槛要求和安全状态检查均通过。

**更多工具 → 获取并校验** 需要 HTTPS 地址、策略和新输出位置。URL 不能包含用户名密码或片段。TLS 与完整 WSEA 校验均通过后才发布文件，已有输出不会被覆盖。TLS 信任来自主程序的环境配置，签名信任来自所选策略。界面不提供关闭这些检查的选项。

## 创建与更新策略

使用 **更多工具 → 创建策略** 或 **更新策略**。附加签名者证书和资源限制位于高级选项中。

| 字段 | CLI 参数 | 初始化 / 更新 |
| --- | --- | --- |
| 新策略文件 | `--output` | 初始化必填，新文件 |
| 现有策略 | `--policy` | 更新必填 |
| 信任根 | `--trust-root` | 初始化必填，可信 CA PEM |
| 回滚状态目录 | `--state-dir` | 仅初始化；已有状态不会重置 |
| 授权证书 | `--certificate` | 初始化或新增模块规则必填，首个 PEM 证书为授权叶证书 |
| 附加签名者证书 | 重复 `--additional-certificate` | 逐个选择文件，最多 7 个；更新时替换全部附加签名者 |
| 清除附加签名者 | `--clear-additional-signers` | 仅更新；不能同时填写附加证书 |
| 多签门槛 | `--signature-threshold` | 初值 `1`，范围 1–8，不能超过不同授权密钥数 |
| 模块标识 | `--module-id` | 初始化及修改模块规则时必填 |
| 允许算法 | `--algorithms` | 初始化默认 `ES256`；更新时全不选保持原集合 |
| 策略版本 | `--policy-version` | 初始化默认 `1`；更新必填且严格递增 |
| 最低模块版本 | `--minimum-version` | 初始化默认 `1` |
| 最低安全纪元 | `--minimum-epoch` | 初始化默认 `0` |
| 能力位掩码 | `--capabilities` | 初始化默认 `0`，范围 0–63 |
| CRL 最大年龄 | `--max-crl-age-seconds` | 初始化默认 `86400` 秒 |
| 模块大小上限 | `--max-module-bytes` | 初始化默认 `104857600` 字节，包含签名 |

更新时，可选项留空表示保留现值；填写 `0` 是明确修改。选择算法会替换允许集合，提供附加证书会替换附加签名者集合。清除附加签名者不能同时添加证书，且门槛必须与剩余签名者数量兼容。修改模块规则时必须填写模块标识。已有安全状态会保留。

提高最低版本或安全纪元可以拒绝旧版本；更新授权证书可以轮换签名者。主程序初始化策略时，可能先创建状态，随后才遇到错误，因此重试前应在本机检查。Web GUI 不会自动重试写操作，也不会重置安全状态。

## JSON 结果与信息隔离

所有 API 响应（包括失败）均为 JSON。界面只读取经过校验并允许返回的字段，展示简洁的结果卡片。**复制 JSON 结果** 复制的是筛选后的文档，不包含本地路径或执行细节。

当前主程序 **没有 `--format json` 参数**。签名、校验和 HTTPS 获取已默认输出 JSON。后端严格解析这些 JSON，拒绝重复键和格式异常的成功结果，并且要求主程序正常退出。策略命令目前输出含本地路径的文本，后端会丢弃文本，只在退出成功时生成 `{"status":"COMPLETED"}`。主程序错误被转换为已知错误码或 `OPERATION_FAILED`，原始错误消息不会返回网页。不会传入不存在的参数，也不需要修改主程序源码。

例如，成功结果文档包含 `status: VERIFIED`，以及模块标识、十进制字符串形式的版本／纪元／能力／时间戳、独立签名者数和贡献算法。未知输出字段、SPKI 列表、ABI 元数据和诊断内容不会转发。`SIGNED_PARTIAL` 是独立的未完成状态；`INVALID_RESULT` 表示无法确认成功结果的格式；`INTERRUPTED` 表示最终写入状态不确定，应先在本机检查再决定是否重试。

同一时间只运行一个操作或文件对话框，对话框五分钟后超时。“最近操作”只在内存中保留最多 20 个筛选后的结果，停止服务后清空。服务器内部文件映射每次会话最多保留 512 个选择。服务不提供文件下载／上传、目录枚举、命令预览、原始输出或环境查询接口。它检查准确的 Host/Origin，使用每次启动生成的令牌、严格 CSP、不开放 CORS，并关闭 HTTP 请求日志。主程序 stdout/stderr 合计限制为 1 MiB，转换结果后即丢弃。

信息隔离边界是 Web API：路径和命令参数必然存在于本机 Python／主程序进程中，不声称防御已被入侵的操作系统或受信任可执行文件。主动选择的文件名和公开签名元数据是有意提供给浏览器的数据。系统文件对话框自身会在本地选择过程中显示路径。

## 开发验证

所有临时数据放在项目 `.tmp/` 下，测试目录及父目录应具有私有权限。测试不会编译主程序。请在 64 GiB、零 swap 的 cgroup 中运行，例如：

```sh
umask 077
mkdir -p .tmp/webgui
systemd-run --user --wait --pipe --collect \
  --property=MemoryMax=64G --property=MemorySwapMax=0 \
  --property=TasksMax=512 --property=CPUQuota=200% \
  --working-directory="$PWD" \
  /usr/bin/env PYTHONDONTWRITEBYTECODE=1 TMPDIR="$PWD/.tmp/webgui" \
  python3 webgui/tests/integration.py \
  --binary /absolute/path/to/cosign --require-cgroup
```

- `test_server.py`：参数边界、会话认证、文件标识用途、旧接口移除、路径／私钥／诊断不外泄、严格 JSON、进程资源限制和后续操作。
- `integration.py`：真实主程序的 13 种算法签名与校验、混合多签、策略更新、权限、篡改拒绝和 TLS。需要本地 OpenSSL。报告和全新测试证书写入新建的 `.tmp/webgui/integration-*`。命令帮助仅在测试进程内用于选项覆盖检查，不会发送给网页。
- `run_frontend.py --binary PATH --fixtures PATH --require-cgroup`：使用集成测试产物启动临时服务器，并运行 `test_frontend.js`。需要 Node.js。验证真实前端状态与 HTTP 代码、双语表单保留、文件标识、两步签名和混合 3/3 签名。系统选择器和 DOM 对象使用测试替身，**不代表**已验证原生对话框外观、浏览器布局或键盘操作；浏览器可用时还应单独检查页面。

每项测试都使用同样的 cgroup 包装运行。测试证书、会话链接、报告、日志和生成密钥不得提交或发布。
