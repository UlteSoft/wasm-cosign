# WSEA v2 安全模型与互操作规则

[English](wasm-secure-execution.en_US.md) | [文档导航](../README.zh_CN.md)

旧 `wasm-cosign` 签名容器已经弃用。新签名使用本文的 `uwvm.wsea.v2`。
两种容器不能互换，修改自定义节名称也不能转换签名；wasm-cosign 项目名称仍继续使用。

`cosign wasm secure` 处理末尾带一个 `uwvm.wsea.v2` 自定义节的 WASM 文件。
其中包含 1 至 8 份签名贡献，每份均包含规范 COSE_Sign1、签名证书链及完整签发者 CRL。
信任根、签名者公钥指纹、算法白名单、权限和防回退存储必须独立供应。
只有显式为模块选择 UWVM `--secure`，才启用执行前第二道检查。

清单域是 `uwvm-wsea-v2`，认证最终签名节之前的每一个原始 WASM 字节。
签名节不能重复，之后也不能存在任何字节；其他所有自定义节同样处于签名覆盖范围内。
VM 的私有执行凭据还绑定完整最终文件。为历史迁移／测试保留的 detached-v1 辅助代码
不代表安全 CLI 或嵌入式执行器接受 v1，也不会回退读取 sidecar 文件。

通过 `policy-init` 和版本严格递增的 `policy-update` 管理本地信任。
`sign` 原子写入已验证的嵌入签名，`--output` 创建新文件，`--replace-signature`
显式替换原签名节。`verify` 校验嵌入证据与本地防回退状态。
`fetch` 验证 HTTPS 的 TLS 身份、限制下载大小、校验 WSEA，再以不覆盖现有文件的方式发布。
网络响应不能改变信任根、策略、公钥授权或 VM 状态。

精确支持 13 种类型：ES256、ESP256、ES384、ESP384、ES512、ESP512、Ed25519、
PS256、PS384、PS512、RS256、RS384、RS512。六字段旧策略保持仅允许 ES256；
启用其他类型必须通过 `--algorithms` 提供不重复的精确名称 CSV。
RSA 要求模数 3072–8192 位、指数 65537；RSA-PSS 要求 SHA-2 与 MGF1 哈希匹配，盐长等于摘要长度。
EC 要求指定的 P-256／P-384／P-521 曲线及定长 low-S 签名。
Ed25519 仅支持纯模式，验证规范公钥／R／S 编码并拒绝小阶点。
通用 EdDSA 名称、Ed448、DSA、SHA-1／MD5 及受限 RSA-PSS SPKI 均不受支持。

证书 SPKI 的位串必须按字节对齐。RSA 参数必须显式为 NULL；EC 使用命名曲线及非压缩点；
Ed25519 参数必须缺省，公钥为 32 字节。PEM 不允许嵌套边界、头字段或尾随 DER。
证书和 v2 CRL 的内外算法标识必须一致。代码签名用途、完整路径验证、证书有效期及
经过身份验证的新鲜 CRL 都是必需条件；撤销列表中任何匹配序列号（包括 removeFromCRL）均拒绝。
VM 永久记住已认证的发行密钥撤销。历史时间戳豁免、异步在线撤销查询不属于离线配置。
管理员、可信 OS 时钟与存储属于本地信任边界。

Go 部署校验只读状态；成功的 VM 校验推进状态。每个被选中的模块加载都独立执行 OpenSSL 校验。
同次加载的初始化凭据随后重新检查不可变完整映像、当前策略、时钟边界和状态，
不重复此前同次加载的全部 PKI 运算。

## 多签名与同厂商版本

单签保持既定编码；2 至 8 份签名使用相同最终 WSEA 节内既有的有界列表，不引入第二种容器。
每份签名必须认证相同模块身份、前缀摘要、长度、ABI、版本、epoch、有效期与能力位。
各份签名允许使用不同的已授权算法、证书和密钥。即使去掉某份后仍满足门槛，
现有的每份签名也必须验证成功；不得忽略无效附加证据来获得成功。

策略授权一个主 SPKI 以及至多七个其他不同 SPKI。门槛按**不同的已授权公钥**计数，
不按签名份数、算法名、证书份数或证书主体名称计数。同一密钥签两次不能算两票。
`--allow-partial` 只允许用于收集签名，不允许校验、下载发布或 VM 执行绕过门槛。

厂商身份由受保护模块规则和 SPKI 集合确定，不由证书展示的组织名决定。
新版本应增加 `--module-version`；对应安全代际变化时增加 `--security-epoch`。
策略最低要求和已学习状态共同约束接受条件。以相同版本发布不同认证内容不是安全发布流程。
密钥轮换应使用严格更高版本的本地策略授权新密钥，设置所需门槛、供应新鲜证据，
并通过受信任的策略／撤销流程退役旧密钥。不得删除状态或撤销标记来让旧版通过。

## 本地存储与时间

策略和信任文件必须由 root 或有效用户控制，不允许符号链接／硬链接替换，不能被组或其他用户写入，
祖先目录同样必须受保护。原生配置允许 root 拥有且带 sticky 位的祖先目录。
状态目录要求私有 0700，状态文件要求 0600，并由有效用户拥有。共享 `.lock` 串行化状态相关操作。
状态缺失、损坏或与防回退记录矛盾时应拒绝，不能自动创建新的最低版本记录。
策略初始化是显式管理员操作。

系统时钟必须可信。校验结果在清单、证书和 CRL 中最早的有效期边界失效。
原生状态检查也会拒绝相对已记录时间下限的时钟回退。
不存在隐含宽限期、UWVM 联网刷新或绕过到期的时间戳例外。

## 可移植 SDK 的边界

WASM SDK 使用相同的固定校验器与算法配置。密码学 reactor 被限定为单线程，不能访问宿主文件或网络。
它不能把内存缓冲区变成受保护的本地存储。`VERIFIED_SNAPSHOT` 表示：所提供的策略、信任根、
状态和完整撤销列表与签名模块在 `checked_at` 时刻共同通过检查，结果仅在排他的 `valid_until` 前有效。

POSIX `run.py` 适配器认证文件、持有共享锁，并在返回 `VERIFIED` 前重新检查信任／状态／到期时间。
浏览器集成者必须在 WASM 外建立同等可信的供应与新鲜度机制。
两类结果都不是 VM 执行凭据；只有接近执行时的显式 UWVM `--secure` 流程才签发并消费该凭据。
两道检查服务于不同时间点，不能相互替代。

## 失败处理与保证范围

非零退出、`REJECTED`、格式错误的 JSON、trap、超时、运行时缺失、密码学后端缺失和熵源失败，
都必须作为失败处理。不得改用旧容器、弱算法、纯 Go PKI 或宿主密码学替代品来重试放行。
诊断前缀包括 `SIG_`（容器／签名／后端）、`CERT_`（证书／签名者／撤销）、
`POL_`（策略、受保护状态、时间或回退）。操作前阅读完整诊断，
更新真实有效的证据或修复受信任部署配置，不得关闭检查。

威胁模型信任管理员、OS、时钟、运行时与受保护存储。
它不保护故意替换信任根的管理员，也不保护完全控制 SDK 宿主的恶意 JavaScript。
资源上限可能导致可移植 SDK 拒绝原生版本可处理的大文件，但不会放宽任何签名接受规则。
测试只能证明已记录的覆盖范围，不能证明不存在任何可能的缺陷。
