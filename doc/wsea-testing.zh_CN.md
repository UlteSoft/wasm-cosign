# WSEA 测试与发行验证

[English](wsea-testing.en_US.md) | [文档导航](../README.zh_CN.md)

## 范围与证据

验证结论只适用于所记录的准确源码、编译器、密码学依赖、运行时和归档字节。
历史成功不能自动证明新编译器或 ABI 合格。生产测试只覆盖 WSEA 的 WASM 产品依赖图，
不能用保留的上游 OCI／任意文件测试替代 WSEA 检查。
崩溃、信号、超时、生成器缺失或运行时不可用都属于失败，不能算作负面校验成功。

原生与 WASM 实现使用相同的已定型 WSEA 容器和 13 种类型。
独立 OpenSSL 样本与原生 UWVM 校验器提供跨实现对照。
测试覆盖双向签名：原生 cosign 签名交给 WASM，以及各 WASM 运行时签名交给其他运行时／原生工具。
必须使用能够执行访客的真实 UWVM CLI，不能以只加载模块的模拟程序替代。

## 本机资源准入

本机 Linux 测试必须在已授权 **64 GiB、零 swap cgroup** 内运行。
进程确实属于被准入的叶节点，且祖先计算出的有效上限同样为 68719476736 字节。
测试前后记录叶节点／启动身份和 OOM 计数，cgroup 改变或 OOM 计数增长均使验证无效。
不得启动约束更弱的子进程，也不能为了通过测试调整上限。

`TMPDIR`、`GOTMPDIR`、Go／Python 缓存、生成私钥、样本、报告与日志均放入项目 `.tmp`，
目录权限 0700、umask 077。限制编译并发、进程数和超时，CI 驱动还禁用 core dump。
macOS 托管原生测试按真实环境标识，不宣称具备 Linux cgroup 覆盖。
发行包与跟踪源码均排除生成的测试资料。

## 原生测试与文档检查

在已通过准入的环境中运行：

```sh
bash scripts/test_wsea_native.sh
python3 scripts/check_wsea_docs.py
```

原生脚本构建固定 OpenSSL、检查产品包、在 Linux 执行 race 测试，并对照 `doc/wsea-cli`
检查自动生成的命令帮助。单元测试覆盖严格 PKI／CRL、算法、多签、畸形容器、状态／快照一致性、
认证 HTTPS 发布、歧义 JSON 成员及全宽计数器。
文档检查器要求两种语言均存在、章节与示例数量相符、代码围栏闭合、本地链接与锚点有效。
它能发现结构不同步，但翻译准确性仍需人工审查。

针对解析器的模糊测试可使用现有 Go 目标，在相同资源边界内设置有限时长和单个 worker。
短时模糊测试不能解释为穷尽密码学验证。

```sh
go test ./pkg/wasmsecure -run='^$' -fuzz=FuzzEmbeddedSectionParser \
  -fuzztime=30s -parallel=1
```

直接 Go 调用需要[构建指南](wsea-build.zh_CN.md)所述捆绑 OpenSSL 环境。

## 完整可移植验证

`ci_wsea.py` 是本机／CI 共用入口。提供位于 `scripts/wsea_uwvm_revision.txt` 指定提交的干净 UWVM
检出目录、固定工具链及新的输出目录。命令必须从已准入 cgroup 内执行，脚本不会静默改变自己的资源边界。

```sh
python3 scripts/ci_wsea.py --uwvm-root .tmp/uwvm --tools .tmp/tools \
  --work .tmp/qualification
```

`--fetch-tools` 先下载并验证固定工具至 `.tmp/tools`，安全解压要求 Python 3.12+ 或包含 data-filter 回移版本。
`--uwvm-cxx` 可明确指定已验证 LLVM 22.1.8 编译器。
`--version v0.2.1` 额外要求产品源码已提交且干净，创建发行归档、提取精确白名单字节，
再对解压出的模块进行验证。不得复用已经完成的工作目录或修改其中构建记录。

驱动构建原生 cosign、完整解释器、真实原生校验器和真正的 Ed25519ph／ctx 生成器，然后创建新鲜样本。
检查包括：

- **277 个矩阵用例**：在 UWVM、Wasmtime、Node 和原生校验器中执行。
  包括全部 13 类型、RSA3072／4096／8192、PSS 参数、EC 标量、规范纯 Ed25519 及真实不支持的 ph／ctx 签名，
  证书／CRL 失败、畸形／旧容器、策略回退和永久撤销。
- **76 项签名／互通检查**：全部类型双向签名、八密钥混合算法门槛、部分签名／重复票拒绝、
  厂商密钥轮换、版本回退、uint64 最大值及超过 2^53 的 epoch、实际 `--secure` 执行与无效贡献拒绝，
  以及三种文件适配器。
- **13 项宿主安全检查**：可写路径、符号链接／硬链接替换、错误或缺失状态、不完整撤销标记、
  宿主 Node 选项注入、校验期间策略替换，以及签名和 OpenSSL 校验两种熵源失败。

矩阵保持各分组已学习的策略／版本／撤销历史。
WASM 快照检查在原生校验器提交下一步状态之前完成，不能在相关负面用例之间重置下限或删除撤销标记。

## 浏览器与其他平台

JavaScript SDK 也适合独立浏览器 Worker。
v0.2.0 验证包含真实 Firefox 的一次校验冒烟测试，其范围小于完整 Node 矩阵，
不能宣称已测试每个浏览器／算法组合。
Web 应用的供应、存储、CSP、权限及密钥生命周期需要自己的集成测试，
应在实际应用环境验证成功／拒绝响应、Worker 终止和安全随机源。

原生跨平台测试使用 `test/wsea/run_go_targets.py`，明确指定 `--native-toolchains`、匹配目标 UWVM
及实际 QEMU 执行。配套 UWVM 安全测试目录提供 HTTPS 和多模块套件。
只有真实构建及测试通过的目标可以发布；缺失目标证据不能由另一架构程序或纯 Go 构建替代。

## 保留资料与处理失败

`.tmp/qualification` 为诊断保留每阶段日志、私有样本和本地 JSON 结果。
发行任务只上传最终白名单生产归档，不能上传整个工作目录、含日期测试项目、私钥、浏览器配置或编译器崩溃复现文件。

工具下载或资源准入失败时，应修复基础环境并在新工作目录重试。
密码学结果不一致时停止发布，对照准确源码／工具／样本身份，并在必要时同步修复两个产品。
修改预期结果或屏蔽失败测试不算通过验证。旧发行文件保持不可变，修正使用新标签。
