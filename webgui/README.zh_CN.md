# WSEA Studio 使用说明

[English](README.en_US.md) · [文档入口](README.md)

WSEA Studio 提供 wasm-cosign 的本地中文、英文操作界面，支持 WASM 签名、验签、多签、HTTPS 获取和策略管理。

## 启动

需要 Python 3.10+ 和已有的 wasm-cosign WSEA v2 原生二进制。Python 仅使用标准库，无需安装额外包；界面不会编译或下载程序。

在仓库根目录运行：

```sh
python3 webgui/server.py \
  --binary /home/you/tools/cosign \
  --browse-root /home/you/releases
```

打开终端打印的完整会话链接，或在登录页面粘贴本次启动的令牌。地址固定为 `127.0.0.1`；请使用打印的地址，不要替换成 `localhost`。刷新页面后重新使用会话链接。按 `Ctrl+C` 停止服务。

右上角 `EN / 中` 切换语言，保留当前表单输入。命令原始输出保持原文，便于查询错误码。

| 参数 | 默认值 | 用途 |
| --- | --- | --- |
| `--binary PATH` | 必填 | 已有原生可执行文件路径，不接受命令串或运行时包装器 |
| `--port N` | `8765` | 本机端口；`0` 自动选择空闲端口 |
| `--browse-root PATH` | 当前目录 | 文件选择器根目录，可重复指定 |
| `--timeout SECONDS` | `120` | 单次操作时限，范围 1–3600 秒 |

业务表单使用干净的绝对路径，不含 `.`、`..` 分量。文件夹按钮可选择已有文件或填写新输出名称。`--browse-root` 只限制文件选择器的浏览范围；也可手动输入其他绝对路径。

服务以启动用户的权限执行操作，使用者须有相应文件权限。会话链接用于授权本地操作，请勿分享或对外转发服务端口。

## 功能

| 页面 | 功能 | 命令 |
| --- | --- | --- |
| 签名工作台 | 创建、追加、替换签名，输出多签中间文件 | `wasm secure sign` |
| 验证模块 | 完整校验模块、证书、CRL、多签门槛和本地状态 | `wasm secure verify` |
| 安全获取 | HTTPS 获取模块，验证通过后保存新文件 | `wasm secure fetch` |
| 创建信任策略 | 设置信任根、签名者、门槛和初始状态 | `wasm secure policy-init` |
| 更新信任策略 | 更新规则、版本、密钥授权与资源限制 | `wasm secure policy-update` |
| 操作记录 | 本次服务会话最近 20 次操作及结果 | — |
| 帮助与环境 | 命令帮助、版本、二进制路径与配置 | `--help`、`version` |

## 签名

### 文件和身份

| 字段 | CLI 参数 | 要求 |
| --- | --- | --- |
| WASM 模块 | `<module>` | 必填，现有模块 |
| 信任策略 | `--policy` | 必填，现有受保护策略 |
| 输出文件 | `--output` | 新文件；原地替换模式不填写 |
| 私钥文件 | `--key` | 必填，PEM，密钥类型与算法匹配 |
| 签名证书链 | `--certificate` | 必填，PEM 叶证书在前，中间证书随后 |
| CRL 证据包 | `--crl` | 必填，完整且有效的 CRL 包 |
| 签名算法 | `--algorithm` | 默认 `ES256`，须在策略允许集合中 |

私钥不能允许组或其他用户访问；策略、信任根、状态文件及父目录须符合程序的路径保护要求。密钥、证书和 CRL 需事先准备。

| 家族 | 可选算法 |
| --- | --- |
| ECDSA | `ES256`, `ESP256`, `ES384`, `ESP384`, `ES512`, `ESP512` |
| EdDSA | `Ed25519` |
| RSA-PSS | `PS256`, `PS384`, `PS512` |
| RSA PKCS#1 v1.5 | `RS256`, `RS384`, `RS512` |

### 清单

| 字段 | CLI 参数 | 格式 / 初值 |
| --- | --- | --- |
| 模块标识 | `--module-id` | 策略中已授权的标识 |
| 模块版本 | `--module-version` | 无符号 64 位整数，初值 `1` |
| 安全纪元 | `--security-epoch` | 无符号 64 位整数，初值 `0` |
| 能力位掩码 | `--capabilities` | `0`–`63`，初值 `0` |
| 生效时间 | `--not-before` | RFC3339 时间，初值为打开页面前 1 分钟 |
| 截止时间 | `--not-after` | RFC3339 时间，初值为打开页面后 24 小时 |

时间中的 `Z` 表示 UTC，截止时间必须晚于生效时间。页面长时间打开后，请检查有效期。版本和数值按完整十进制字符串处理，不丢失 64 位整数精度。

### 签名方式

- **创建签名**：为未签名模块创建签名。
- **追加多签**：保留已有签名，并使用 `--append-signature` 追加贡献。所有清单字段必须相同。
- **替换签名**：使用 `--replace-signature` 替换模块中全部已有签名。
- **原地替换输入文件**：原子写回输入文件；关闭时必须提供新的输出路径。新输出不会覆盖已有文件。
- **允许多签中间文件**：使用 `--allow-partial` 在未达门槛时输出 `SIGNED_PARTIAL`，供后续追加。

## 多签操作

以 ECDSA、RSA、Ed25519 的 3/3 策略为例：

1. 创建策略：指定一个主签名者证书、两个附加证书、所需信任根，允许 `ES256,RS256,Ed25519`，门槛设为 `3`。
2. 为原始模块填写共同清单和第一名签名者材料，开启中间文件选项，保存新文件。
3. 结果显示“中间签名 · 尚未达门槛”。点击“继续追加另一签名”：模块路径和清单会沿用，密钥、证书、CRL、输出路径会清空。
4. 选择第二名签名者材料，保持中间文件选项，完成第二次签名。
5. 追加第三名签名者，关闭中间文件选项，要求完整门槛通过。
6. 点击“转到完整验签”进行独立验证。

最多支持 8 份签名贡献。门槛按**不同授权公钥 SPKI**计数；同一密钥重复签名不会增加独立签名者数量。结果分别列出独立 SPKI 和各贡献使用的算法。

`SIGNED_PARTIAL` 不能通过完整验签或安全获取。追加时，已有签名也必须有效。

## 创建和更新策略

| 字段 | CLI 参数 | 初始化 / 更新 |
| --- | --- | --- |
| 新策略文件 | `--output` | 初始化必填，新文件 |
| 现有策略 | `--policy` | 更新必填 |
| 信任根 | `--trust-root` | 初始化必填，可信 CA PEM |
| 回滚状态目录 | `--state-dir` | 仅初始化；已有状态不会重置 |
| 授权证书 | `--certificate` | 初始化或新增模块规则必填，首个 PEM 证书为授权叶证书 |
| 附加签名者证书 | 重复 `--additional-certificate` | 每行一个绝对路径，最多 7 个；更新时替换全部附加签名者 |
| 清除附加签名者 | `--clear-additional-signers` | 仅更新；不能同时填写附加证书 |
| 多签门槛 | `--signature-threshold` | 初值 `1`，范围 1–8，不能超过不同授权密钥数 |
| 模块标识 | `--module-id` | 初始化及修改模块规则时必填 |
| 允许算法 | `--algorithms` | 初始化默认 `ES256`；更新时全不选保持原集合 |
| 策略版本 | `--policy-version` | 初始化默认 `1`；更新必填且严格递增 |
| 最低模块版本 | `--minimum-version` | 初始化默认 `1` |
| 最低安全纪元 | `--minimum-epoch` | 初始化默认 `0` |
| 能力位掩码 | `--capabilities` | 初始化默认 `0`，范围 0–63 |
| CRL 最大年龄 | `--max-crl-age-seconds` | 初始化默认 `86400` 秒 |
| 模块大小上限 | `--max-module-bytes` | 初始化默认 `104857600` 字节，包含签名 |

更新页的可选字段**留空保持原值**；输入 `0` 是明确修改。选择算法或填写附加证书会替换集合，不是在原集合上追加。清除签名者时应同步设置兼容的门槛。更新策略保留已有状态。

提高最低模块版本或纪元后，较旧模块会被拒绝。密钥轮换通过更新授权证书完成。

初始化失败时可能已创建状态目录或文件，请检查实际结果后再操作，不要重置已有安全状态。

## 验签和 HTTPS 获取

**验证模块**只需模块与策略。成功必须满足所有签名检查和策略门槛。

**安全获取**填写完整模块的 HTTPS URL、策略和新输出路径。URL 不能携带用户名、密码或片段。TLS 验证与完整 WSEA 校验通过后才保存；已有输出不覆盖。HTTPS 的 TLS 信任使用二进制所在环境，WSEA 的签名信任使用所选策略。

## 结果与记录

| 状态 | 含义 |
| --- | --- |
| 完整验签通过 | 返回 `VERIFIED`，命令退出码为 0 |
| 中间签名 | 返回 `SIGNED_PARTIAL`，还需追加签名 |
| 操作已完成 | 策略、帮助或版本命令完成 |
| 操作未通过 | 非零退出或结果格式错误；查看原始输出和错误码 |
| 操作中断 | 超时、停止服务或输出超限；检查实际文件状态后再决定是否重试 |

每次可执行一个命令。可预览实际命令、展开原始输出与完整清单、复制结果。操作记录保留最近 20 条，重启服务清空。单次输出上限为 1 MiB，不自动重试操作。

## 开发验证

测试文件在 `webgui/tests/`；临时材料和结果只写到项目 `.tmp/`。

- `test_server.py`：参数、会话认证、请求边界、进程超时和输出限制。
- `integration.py --binary PATH`：使用已有二进制测试全部命令、13 种算法、多签和 HTTPS；需要本机 `openssl`。

Linux 64 GiB、零 swap cgroup 示例：

```sh
mkdir -p .tmp/webgui
systemd-run --user --wait --pipe --collect \
  --property=MemoryMax=64G --property=MemorySwapMax=0 \
  --property=TasksMax=512 --property=CPUQuota=200% \
  --working-directory="$PWD" \
  /usr/bin/env PYTHONDONTWRITEBYTECODE=1 TMPDIR="$PWD/.tmp/webgui" \
  python3 webgui/tests/integration.py \
  --binary /absolute/path/to/cosign --require-cgroup
```

边界测试使用相同 cgroup 命令，将最后两行替换为 `python3 webgui/tests/test_server.py`。集成测试报告位于新建的 `.tmp/webgui/integration-*/report.json`。升级二进制后重新运行测试；命令帮助覆盖检查会检测 GUI 未覆盖的新参数。
